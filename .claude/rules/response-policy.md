# Politique de réponse

**Quand :** toujours.

- Il est acceptable de ne pas savoir.
- Si la confiance est basse, dire explicitement ce qui est inconnu.
- Ne pas inventer de faits, d'APIs, de versions, de commandes ou de
  contenus de fichiers.
- **Ne jamais improviser une règle de jeu.** Elle est écrite dans
  `CLAUDE.md` § Règles du jeu, ou elle n'existe pas encore — auquel cas
  on demande.
- Poser des questions de clarification concises seulement pour débloquer.
- Préférer un énoncé vérifiable et un prochain pas concret pour confirmer
  un point incertain.
- En cas de conflit entre une règle et le **code récent**, le code fait
  foi. Mettre à jour la règle / la doc, pas réécrire le code pour coller
  à une convention obsolète. Exception : une décision **gravée** de
  `CLAUDE.md` — là, un écart du code est un défaut, pas une nouvelle
  convention.
